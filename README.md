# ⚔ IndieForge AI

> AI-powered structured content generator for videogames and fictional worlds.  
> Built end-to-end with **Bun** — no Node.js, no Express, no Vite.

---

## 1. What it does

IndieForge AI helps indie game developers and worldbuilders instantly generate **structured, ready-to-use game content** with a fine-tuned 0.6B language model:

| Type | Output |
|------|--------|
| 🧙 NPC | name, role, race, personality, secret, dialogue line |
| ⚔️ Quest | title, type, objective, reward, location, twist |
| 💎 Item | name, type, rarity, description, effect, value |
| 📜 Lore | title, era, summary, factions, secret |

Every output is a clean **JSON object** — copy it and paste it directly into your game engine.

**Why it's good for 0.6B models:**
- All outputs are short (< 256 tokens)
- Fixed JSON schema: the model just fills slots
- Fallback system kicks in if the model has a bad day
- The backend controls all validation — the model just generates text

## 2. Architecture

```
Browser (React SPA)
        │  fetch /api/*
        ▼
Bun.serve() — server.ts
  ├── POST /api/generate  → callModel(HF) → parseJSON → validateOrFallback → DB → response
  ├── GET  /api/history   → DB query → response
  ├── POST /api/favorite  → DB insert → response
  ├── GET  /api/favorites → DB query → response
  └── GET  /*             → serve frontend/index.html + frontend/app.js

SQLite (bun:sqlite)          Hugging Face Inference API
  indieforge.db                 fine-tuned 0.6B model
```

## 4. Quick Start

### Prerequisites
- [Bun](https://bun.sh) ≥ 1.1
- A Hugging Face account + fine-tuned model + API token

### Setup

```bash
# 1. Clone & install
cd IndieForgeAI-hackaton-main
bun install

# 2. Configure environment
cp .env.example .env
# Edit .env — set HF_TOKEN and HF_MODEL_URL

# 3. Build frontend
bun run build

# 4. Start
bun run dev          # hot reload
# or
bun run start        # production
```

Open [http://localhost:3000](http://localhost:3000).

## 6. API Reference

### `POST /api/generate`

```json
// Request
{ "type": "npc", "genre": "Fantasy", "role": "Merchant", "name": "Aldric" }

// Response
{
  "success": true,
  "data": {
    "id": 1,
    "type": "npc",
    "source": "model",
    "result": {
      "name": "Aldric",
      "role": "Merchant",
      "race": "Human",
      "personality": "Jovial but hides a dark past",
      "secret": "Sold forbidden relics to the Crimson Guild",
      "dialogue": "Everything has a price, friend."
    }
  }
}
```

### `GET /api/history?limit=20`

Returns last N generations for the current session.

### `POST /api/favorite`

```json
{ "generation_id": 42 }
```

### `DELETE /api/favorite`

```json
{ "generation_id": 42 }
```

### `GET /api/favorites`

Returns all favorited generations for the session.

## 7. Database Schema

```sql
-- generations: every AI output
CREATE TABLE generations (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id  TEXT NOT NULL,
  type        TEXT NOT NULL,          -- npc | quest | item | lore
  prompt_meta TEXT NOT NULL,          -- input params as JSON string
  result      TEXT NOT NULL,          -- output as JSON string
  raw_output  TEXT,                   -- raw model text (for debugging)
  source      TEXT NOT NULL,          -- 'model' or 'fallback'
  created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- favorites: saved generations per session
CREATE TABLE favorites (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id     TEXT NOT NULL,
  generation_id  INTEGER NOT NULL REFERENCES generations(id) ON DELETE CASCADE,
  created_at     TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE (session_id, generation_id)
);
```

## 8. Prompt Engineering

Each type uses a strict fixed-schema prompt:

**NPC:**
```
Generate a fantasy NPC named Aldric who is a merchant.
Respond ONLY with valid JSON matching this exact schema, nothing else:
{"name":"string","role":"string","race":"string","personality":"string (max 15 words)","secret":"string (max 15 words)","dialogue":"string (max 20 words)"}
```

**Quest, Item, Lore** follow the same pattern — see [`src/lib/prompts.ts`](src/lib/prompts.ts).

## 9. Parser + Fallback Strategy

```
Model output
    │
    ├─ try: JSON.parse(raw)
    ├─ try: extract first {...} block
    ├─ try: strip markdown fences → extract {...}
    │
    ├─ VALID → validate required fields → sanitize strings → save
    │
    └─ INVALID / model error
           → getFallback(type, meta)   ← pool of 3 handcrafted entries per type
           → save with source="fallback"
```

The fallback pool ensures the demo **always works**, even with no HF token.

## 10. What NOT to do with a 0.6B model

- ❌ Complex multi-step reasoning ("plan a full campaign with branching dialogue")
- ❌ Long texts (> 300 words essays, chapters, detailed backstories)
- ❌ General chatbot ("answer any question the user has")
- ❌ Code generation
- ❌ Arithmetic or logic puzzles
- ❌ Open-ended instructions without a fixed schema to fill
- ❌ Multilingual outputs (stick to the training language)

## 11. Docker Deployment (Coolify / Dokploy)

```bash
# Local test
docker compose up --build

# Production: set env vars in your deploy platform
# HF_TOKEN=hf_...
# HF_MODEL_URL=https://api-inference.huggingface.co/models/...
```

The `Dockerfile` uses a two-stage build:
1. `oven/bun:1` — builds the frontend
2. `oven/bun:1-slim` — runs the server (smaller image)

Data persists in a Docker volume (`app_data:/data`).
